## 0. ความรู้เชิง business / การแพทย์ที่ได้จากผู้ใช้ (domain rules)

เรื่องที่ไม่ได้อยู่ในโค้ดหรือเอกสารเดิม ได้มาระหว่างออกแบบร่วมกับผู้ใช้ ใช้เป็นกติกาตัดสินใจ

| # | กติกา | ผลต่อการออกแบบ |
|---|---|---|
| 1 | แต่ละบทบาทรู้ข้อมูลต่างกัน: ข้อมูลเหตุการณ์ (หมวกนิรภัย เข็มขัด แอลกอฮอล์ ยานพาหนะ การดูแลก่อนมาถึง) ได้จากผู้ป่วย/ญาติ/ผู้นำส่ง ตอน **คัดกรอง** แพทย์ไม่มีทางรู้ | ฟอร์มแยกตามบทบาท แพทย์/พยาบาล ER/พยาบาลคัดกรอง ห้ามถามข้ามบทบาท |
| 2 | ข้อมูลคัดกรองพยาบาลบันทึกแล้ว แพทย์แค่ **ทบทวนและยืนยัน** ไม่กรอกซ้ำ | ขั้นแรกของแพทย์ = ยืนยันข้อมูลคัดกรอง + แพ้ยา |
| 3 | แพทย์ที่มาดูผู้ป่วย ER บางคนเป็น **แพทย์เฉพาะสาขา** (กระดูก สูติ ศัลย์ ฯลฯ) ตรวจเฉพาะระบบของตน ระบบอื่นไม่ได้ตรวจ | template ตรวจร่างกาย = ขอบเขตระบบของสาขา · ระบบนอกขอบเขต = "ไม่ได้ตรวจ" |
| 4 | ผลตรวจ **ผิดปกติต้องมีคำอธิบายเสมอ** (เวชระเบียนต้องบอกว่าผิดปกติอย่างไร) | บังคับรายละเอียด ยืนยันไม่ได้จนกว่าจะใส่ |
| 5 | HPI ในฟอร์มจริงเป็น **ข้อความช่องเดียว** แพทย์เขียนเป็นย่อหน้าตามแบบแผน (OLDCARTS / กลไกการบาดเจ็บ) | ไม่แตกเป็นหลายช่อง ใช้ template ย่อหน้าที่มี [ ] ให้เติม |
| 6 | รหัสหัตถการ ICD-9-CM ผูกกับหัตถการแน่นอน (เช่น เย็บแผล → 86.59) | แนะนำจาก master ไม่ให้ AI เดารหัส |
| 7 | ตำแหน่งบาดแผลระบุด้วยส่วนของร่างกาย + ข้าง (ซ้าย/ขวาของผู้ป่วย) | แตะบนหุ่น 3D แล้วแปลงเป็นชื่อส่วน+ข้าง |
| 8 | ห้อง ER มีเสียงรอบข้างตลอด (คนคุยกัน อุปกรณ์) ไมค์เปิดค้างจะรับเสียงที่ไม่เกี่ยวกับเคส | กดค้างเพื่อพูด · ห้ามเปิดไมค์เอง · ต้องมีหน้าสรุปยืนยันก่อนบันทึก |
| 9 | แพทย์ต้องการเห็น **แนวโน้มระหว่างการตรวจแต่ละครั้ง** (แย่ลง/ดีขึ้น/พบใหม่) มากกว่าผลครั้งเดียว | แท็บตรวจร่างกายเป็นไทม์ไลน์เทียบครั้งก่อน |
| 10 | ข้อมูลที่หน้าจอแสดงอยู่แล้ว ผู้ช่วยไม่ต้องพูด/แสดงซ้ำ แพทย์ต้องการคำตอบสั้นแบบวิทยุ | ผู้ช่วยตอบ ≤ 2 ประโยค และไม่สร้างการ์ดข้อมูลซ้ำ |
| 11 | อาการที่ไม่ระบุอวัยวะชัด (ปวดท้อง คลื่นไส้) ไม่ควรชี้อวัยวะใดอวัยวะหนึ่ง | แสดงเป็น heatmap โซน ไม่ map อวัยวะ |
| 12 | ทุก workflow ต้อง **ยืนยันก่อนบันทึก** เห็นสรุปทุกช่องอีกครั้ง | หน้าสรุปก่อนบันทึกท้ายทุกขั้น |

## 2. บทบาทและ workflow ของโหมดพูด

แต่ละบทบาทกรอก **เฉพาะฟอร์ม HOSxP ที่เป็นของบทบาทนั้น** (`role` ใน `er_form_kb.json`)
กติกา: ห้ามถามข้อมูลที่บทบาทนั้นไม่มีทางรู้ เช่น แพทย์ไม่ถามเรื่องหมวกนิรภัย/แอลกอฮอล์ (เป็นงานพยาบาลคัดกรองที่ถามผู้ป่วย ญาติ หรือผู้นำส่ง)

| บทบาท | ขั้น (orbit) |
|---|---|
| แพทย์ ER | ทบทวนเคส (ยืนยันข้อมูลคัดกรอง/แพ้ยา) → ประวัติ HPI → ตรวจร่างกาย → บาดแผล/หัตถการ → วินิจฉัย/สั่ง → จำหน่าย |
| พยาบาล ER | สัญญาณชีพ → ความรุนแรง AIS → รับคำสั่งแพทย์ → สังเกตอาการ → การพยาบาล → ออกจาก ER |
| พยาบาลคัดกรอง | รับเข้า → อาการสำคัญ → สัญญาณชีพ → GCS/รูม่านตา → อุบัติเหตุ → ระดับ ESI |

ค่าคงที่ในโค้ด: `_doctorSteps/_doctorForm/_doctorAsk`, `_nurse…`, `_triage…` และ `_kbFor(step)` เลือกส่วนของ KB ที่ส่งให้ LLM

### หน้าในแต่ละขั้น (ลำดับการนำเสนอ)

1. การ์ดที่ต้องลงมือทำ (เวลาเป้าหมาย, ชุดคำสั่ง, เลือก template ตรวจร่างกาย ฯลฯ)
2. ฟอร์มครบทุกช่องของขั้น แบบ **flipbook** ทีละช่อง
3. **หน้าสรุปก่อนบันทึก** (ช่อง → ค่า แตะเพื่อแก้) ยืนยันได้เมื่อครบเท่านั้น ครบแล้วระบบพาไปหน้านี้เอง

ตัวควบคุม `‹ n/N ›` นับรวมทุกหน้า (ฟอร์มนับ 1 หน้าต่อช่อง) · สารบัญลอยซ้ายของแผงผู้ช่วย ขอบบนตรงกัน

## 3. Generative UI ของผู้ช่วย

- LLM ตอบ JSON: `reply`, `fields`, `choices`, `intent`, `ui` (บล็อกตามแค็ตตาล็อก `erUiCatalogPrompt`)
- บล็อกที่แสดงตัวเลขผู้ป่วย (vitals, labs, imaging) ส่งแค่ **ชื่อ** แอปดึงค่าจริงเอง ผู้ช่วยแต่งตัวเลขไม่ได้
- **ห้ามแสดงซ้ำข้อมูลที่หน้าแสดงอยู่แล้ว**: บล็อก vitals / labs / imaging / brief / alert แพ้ยา ถูกตัดทิ้งตามชนิด (`_spotOf`) ไม่ขึ้นกับแท็บ
- ฟอร์มและหน้าสรุปยืนยันมาจากขั้นเสมอ ผู้ช่วยส่ง form / next_step มาแทนไม่ได้
- ตอบสั้น: prompt จำกัด 10–15 คำ และ `_brief()` ตัดเหลือ 2 ประโยคก่อนแสดง/สร้างเสียง
- สิ่งที่ผู้ใช้ปฏิเสธไปแล้ว (อย่าทำซ้ำ): แผ่นการ์ดลอยกลางจอ, deck ใหญ่, spotlight ชี้แผงเดิม

## 4. ช่องกรอกและ master data

- ตัวเลือกมาจาก `er_master_data.json` ก่อน แล้วค่อย KB แล้วค่อย hint
- ช่องโหมดพูดที่รวมหลายช่องจริง จับคู่ตารางด้วย `_fieldTables` (เช่น `GCS (E / V / M)` → gcs_eye/verbal/motor) · `"id|ชื่อ"` = ใช้ตารางซ้ำ (รูม่านตาซ้าย/ขวา) · ค่าเก็บแบบ `a · b` ตามตำแหน่ง
- 2–4 ตัวเลือก = ปุ่มใหญ่เต็มแถว สีตามความหมาย (ปกติเขียว ผิดปกติแดง ไม่ได้ตรวจเทา) · ≤ 8 = ชิป · มากกว่า = รายการค้นหาได้ (`_listSheet`)
- ข้อความยาว: กล่องแก้ไข 4–12 บรรทัด
- คำย่อมีคำอธิบายสั้นใต้ชื่อ (`_terms`) เช่น HEENT → ศีรษะ ตา หู จมูก คอ

### ช่องพิเศษ

| ช่อง | พฤติกรรม |
|---|---|
| HPI | มี template 7 แบบ (`_hpiTemplates`) แนะนำตามประเภทผู้ป่วย · ผู้ช่วยเรียกใช้ด้วย `"hpi_template":"<id>"` แล้วเติม `[ ]` จากคำบอกเล่า ห้ามเดา |
| ตรวจร่างกาย | ทุกระบบมีช่องรายละเอียดอิสระ `"<ระบบ> - รายละเอียด"` · ช่อง "บันทึกการตรวจแบบละเอียด" ท้ายฟอร์ม (= ช่อง "บันทึกการตรวจร่างกาย" ของ HOSxP) · เลือก "ผิดปกติ" แล้วไม่พลิกหน้าเอง |
| Template ตรวจร่างกาย | หน้าแรกของขั้นตรวจร่างกาย = เลือก template · template = **ขอบเขตระบบที่สาขานั้นตรวจ** ระบบนอก template บันทึก "ไม่ได้ตรวจ" และตัดออกจาก flipbook/สารบัญ (`_peScope`, `_stepLabels`) · สร้าง/แก้/ลบในหน้าต่างแยก (`_openPeTemplates`) · เก็บ `shared_preferences` แยกผู้ใช้ · ผู้ช่วยใช้ด้วย `"pe_template":"<ชื่อ>"` |
| ผลตรวจ "ผิดปกติ" | บังคับรายละเอียดเสมอ: เลือกแล้วเปิดกล่องพิมพ์ทันที · ยังไม่ใส่ = ช่องไม่ครบ (`_fieldDone`/`_needsDetail`) ยืนยันบันทึกไม่ได้ |
| ตำแหน่งบาดแผล | แตะบนหุ่น 3D → หา rig bone ใกล้สุด → ชื่อส่วน+ข้าง (เช่น ต้นขาขวา) + หมุดแดง · rig ใช้ `Hip` = ต้นขา, `Palm` = มือ |
| ICD-9-CM | แนะนำจาก master `er_procedure.icd9cm` (ไม่ใช่ LLM เดา) · เลือกหัตถการแล้วเติมให้ทันทีถ้าว่าง |

## 5. ไมค์ / เสียง

- **กดค้างเพื่อพูด** ปล่อยเพื่อส่ง (กด < 0.4 วิ หรือไม่ได้ยินเสียงพูด = ยกเลิก · นานสุด 60 วิ)
- ไม่เปิดไมค์เองหลังผู้ช่วยพูด (เคยทำให้เสียงรอบห้องกรอกฟอร์ม/เลื่อนขั้นเอง)
- แยกเสียงพูดจากพื้นหลังห้องด้วย `_dbFloor` (ดังกว่าพื้นหลัง 12 dB)
- สถานะใต้ปุ่ม: กดค้างเพื่อพูด / ปล่อยเพื่อส่ง mm:ss (+ มิเตอร์) / กำลังประมวลผล / น้องช่วยกำลังพูด · คลื่นเสียงรอบปุ่มตามความดังจริง
- บริการ (OpenAI-compatible, BMS Cloud): LLM `vllm-gemma` / `vllm-qwen` (เร็ว), ASR `asr2`, TTS `vox-cpm` · ผู้ช่วยใช้เสียงผู้หญิง "น้องช่วย" ลงท้าย ค่ะ/คะ
- ยังค้าง: ความยินยอมส่งข้อมูลผู้ป่วยขึ้นคลาวด์ (PHI)

## 6. ฉาก 3D และ body map

- หุ่นและกายวิภาคมาจาก **BodyParts3D** เท่านั้น ห้ามปั้นเอง (ต้องรองรับทุกอวัยวะ) · spleen/thyroid ไม่มีใน BP3D 4.0
- **ไม่ยุ่งกับชั้นเส้นเลือด** (ไม่ map และไม่โหลด)
- map อาการ → อวัยวะ/กระดูก ต้องเป็น logic ห้าม hard code ต่อเคส (`er_body_map.dart`)
  - กระดูกหัก = กระดูกชิ้นนั้นสีแดง · อาการไม่ระบุตำแหน่ง (ปวดท้อง คลื่นไส้) = heatmap โซน
  - แสดงแบบ x-ray เฉพาะจุด ที่เหลือเป็นผิว รองรับหลายจุดต่อเคส
- ห้ามวางชั้นทับเต็มจอ (BackdropFilter/ClipPath/CustomPaint เจาะรู) บน WebView 3D — Impeller (Vulkan) วาดหน้าหายทั้งแผ่นโดยไม่มี error
  - เบลอครึ่งล่างตอนโหมดพูดใช้ `ShaderMask` + `BackdropFilter` แนวตั้งได้ (ทดสอบแล้ว)
- แก้ JS ในฉากหรือ asset ต้อง hot restart (`R`) ไม่ใช่ reload

## 7. แท็บของแฟ้มผู้ป่วย

ภาพรวม · คัดกรอง · ตรวจร่างกาย · คำสั่งแพทย์ · สัญญาณชีพ · ยา · แล็บ · ภาพถ่าย · ฟอร์ม HOSxP (index 0–8)

- ส่วนโหมดพูดต้องเหมือนเดิมทุกแท็บ
