# ER Module — Design Principles & Rules

กติกา design language ของโมดูล ER (HOSxP Plus V5 · แท็บเล็ตแนวนอน)
**ทุกคนที่มาทำต่อ (คนหรือ AI) ต้องอิงเอกสารนี้** ถ้าจะออกนอกกติกา ให้คุยกับทีม UX/UI แล้วแก้เอกสารนี้ก่อน ห้ามแก้แค่ในโค้ด

- โค้ดอ้างอิง: `lib/er/er_flow_home/core/theme.dart` (สี token · `_t()` · gloss helper) · การ์ด `_clyCardDeco` อยู่ใน `features/patient/overview_panel.dart`
- กติกาด้านการแพทย์/business: `docs/knowledge.md` หัวข้อ 0
- ภาพตัวอย่าง: `docs/screenshots/er-redesign/`

ลำดับความสำคัญเวลาขัดกัน: **ความปลอดภัยผู้ป่วย > ข้อมูลจริง > อ่านออกในห้อง ER > ความสวยงาม**

## 1. หลักการ (Principles)

| # | หลักการ | ในทางปฏิบัติ |
|---|---|---|
| P1 | **แสดงเฉพาะข้อมูลที่มีจริง** | ห้ามแต่งตัวเลข คะแนนเสี่ยง KPI หรือการ์ดสรุปที่ไม่มีที่มาในข้อมูลเคส ไม่มีข้อมูล = ไม่แสดง (ไม่ใส่ placeholder ปลอม) |
| P2 | **เห็นสิ่งผิดปกติก่อน** | สีเน้นโผล่เฉพาะตอนผิดปกติ ค่าปกติใช้สีตัวอักษรธรรมดา ผู้ใช้กวาดตาแล้วเจอสีแดง = เรื่องที่ต้องทำ |
| P3 | **เฉพาะที่แพทย์/พยาบาลสนใจ** | ตัดข้อมูลรองออก ข้อมูลเยอะไม่ใช่ข้อมูลดี ถ้าไม่ใช้ตัดสินใจในเคสนี้ อย่าวางบนหน้าแรก |
| P4 | **ทำทีละขั้น** | งานบันทึกแบ่งเป็น step · หนึ่งหน้าหนึ่งเรื่อง · มีหน้าแนะนำก่อนเริ่ม · มีหน้าสรุปก่อนบันทึกเสมอ |
| P5 | **กดง่าย ใช้มือเดียว** | ปุ่มหลักอยู่ขอบล่าง ขนาดแตะ ≥ 40px · ใช้แตะ (tap) ไม่ใช้กดค้าง |
| P6 | **ต่อเนื่อง ไม่กระโดด** | ทุกการเปลี่ยนหน้า/ขยายแผงมี animation สั้น ๆ บอกทิศทาง |
| P7 | **ลื่นก่อนสวย** | เอฟเฟกต์ที่ทำให้เฟรมตก ห้ามใช้ (ดูหัวข้อ 8) |
| P8 | **AI ช่วย ไม่ตัดสินแทน** | AI เติม/แนะนำ ผู้ใช้ยืนยันเสมอ ทุกค่าที่ AI เปลี่ยนต้องเห็นว่าเปลี่ยนอะไร |

## 2. สี (Color)

### กฎ 60-30-10

| สัดส่วน | บทบาท | Token |
|---|---|---|
| 60 | พื้นและแผง | `_bg` `#EDEDED` · `_panel` `#FFFFFF` · `_panelSoft` `#F1F3F4` · `_line` `#E3E6EA` |
| 30 | โครงสร้าง ตัวอักษร สีหลัก | `_inkTitle` `#14181B` · `_ink` `#202124` · `_ink2` `#474C52` · `_ink3` `#6B7178` · `_blue` (navy) `#001B7C` |
| 10 | สีเน้น (เฉพาะผิดปกติ/สำคัญ) | `_red` `#D93025` |

ไล่เฉด navy สำหรับแยกลำดับในตระกูลเดียว: `_blue2` `#2B3F96` · `_blue3` `#5A69B4` · `_blue4` `#9AA3D2`

### ข้อยกเว้นที่อนุญาต (มีแค่นี้)

| สี | ใช้กับ | ห้ามใช้กับ |
|---|---|---|
| ESI 1 `#BE1E2D` · 2 `#AF1EBE` · 3 `#DC8610` · 4 `#006838` · 5 `#465054` | ป้ายระดับความเร่งด่วนเท่านั้น | อย่างอื่นทั้งหมด |
| `_green` `#1E9E5A` | ขั้นตอนที่ทำครบแล้ว (step ✓, "ครบแล้ว") | สถานะ "ปกติ" ของค่าแล็บ/vital sign |
| `_red` บนยา STAT | ช่องติ๊ก "ยา STAT" ตอนติ๊กแล้ว + ป้าย STAT ข้างชื่อยา (ให้ทันที) | ยาที่ไม่ใช่ STAT |
| สี pain score | pill Pain บนหัวผู้ป่วย: พื้นสีตามสีของหน้า icon HOSxP+ ระดับนั้น (0 ฟ้า → 2–3 เขียว → 5 เหลือง → 8 ส้ม → 10 แดงเข้ม) | ที่อื่นนอก pill pain score |

### กฎ

- **แดง = ผิดปกติ/อันตราย/แจ้งเตือนวิกฤต** เท่านั้น: แพ้ยา, ค่า H/L, แจ้งเตือนครบเวลา ห้ามใช้แดงเป็นสีตกแต่ง
- ห้ามเพิ่มสีใหม่ (เหลือง ฟ้า ม่วง ฯลฯ) นอกตารางข้างบน
- ห้าม hardcode hex ใน widget ใหม่ ใช้ token เสมอ
- บนพื้น navy ใช้ชุด `_pInk*` (ขาวโปร่ง) และ `_onDark(c)` ดันสีเน้นให้อ่านออก

## 3. ตัวอักษร (Typography)

- ฟอนต์เดียว: **IBM Plex Sans Thai Looped** (`IBMPlexSansThaiLooped` ฝังในแอป ไม่โหลดจากเน็ต · น้ำหนัก 400/500/600/700)
- สร้างสไตล์ผ่าน `_t(size, color:, weight:)` / `_num(...)` เท่านั้น
- **น้ำหนักต่ำสุด Medium (w500)** — `_minW` ดัน w300/w400 ขึ้นเป็น w500 อัตโนมัติ ห้ามข้าม
- ใช้ w500 / w600 / w700 เป็นหลัก · w800 เฉพาะตัวเลขใหญ่มาก

| บทบาท | ขนาด (logical px) | น้ำหนัก | สี |
|---|---|---|---|
| หัวข้อหน้า/แผง | 13 – 14 | w700 | `_inkTitle` |
| หัวข้อการ์ด | 11.5 – 12.5 | w700 | `_ink` |
| เนื้อหา | 10.5 – 11 | w500–w600 | `_ink` / `_ink2` |
| label / meta | 9 – 10 | w600 | `_ink3` |
| ป้ายเล็ก (chip, badge) | 8.5 – 9.5 | w700 | ตามพื้น |

- ข้อความ UI เป็นภาษาไทย ศัพท์การแพทย์ที่หน้างานใช้เป็นอังกฤษให้คงอังกฤษ (HPI, GCS, CC, ESI, Order Set)
- ตัวเลขที่เรียงเทียบกันใช้ความกว้างคงที่ (tabular)
- **อายุแสดงเป็น "ปี เดือน วัน" เสมอ** ผ่าน `ErCase.ageText`

## 4. รูปทรงและมิติ (Shape & Depth)

### มุมโค้ง

| ขนาด | ใช้กับ |
|---|---|
| 100 (pill) | ปุ่ม, chip, badge, pill |
| 14 | การ์ดหลัก / แผงลอย (workflow panel) |
| 12 | การ์ดข้อมูล (`_clyCardDeco`) |
| 10 | การ์ดย่อย / tile (`_clyTileDeco`) |
| 8 | ช่องกรอก, ปุ่มสี่เหลี่ยมเล็ก |
| 4 – 6 | แถบ progress, ตัวบ่งชี้เล็ก |

### ความนูนแบบ 3D (gloss) — ใช้ helper เท่านั้น

| Helper | ใช้กับ |
|---|---|
| `_clyCardDeco` | การ์ดข้อมูล: gradient ขาว→เทาอมฟ้าจากซ้ายบน + เงาลอย 2 ชั้น |
| `_clyTileDeco({edge})` | การ์ดย่อย: gradient บน→ล่าง + เงาเล็ก · `edge: _red` เมื่อผิดปกติ |
| `_glossGrad(color)` | พื้นปุ่ม/ป้ายสี (สว่างบน เข้มล่าง) |
| `_glossWhite` | พื้นปุ่มขาว |
| `_glossLift(color)` | เงานูนใต้ปุ่ม/ป้าย |
| `_InnerGloss(radius, dark:)` | เงาด้านในแบบเล่นแสง ใส่เป็น `foregroundDecoration` |

- แสงมาจาก **ด้านบน/ซ้ายบน** ทุกชิ้น ห้ามกลับทิศ
- เงาใช้สี navy เข้ม `#0B1B3F` โปร่ง 5–22% ห้ามใช้ดำล้วน
- **ห้ามใช้ blur** (`BackdropFilter`, `MaskFilter.blur`) ทำ raster ช้า ~50ms/เฟรม
- แสงสะท้อนอยู่ใน gradient พื้น ไม่วาดทับเนื้อหา (ตัวอักษรต้องไม่ซีด)
- ไม่ใช่ทุกอย่างเป็นการ์ด: ฟอร์มใน workflow **ไม่มีการ์ดครอบ** · แผงขวา **ไม่มี outer card**

## 5. Layout

- จออ้างอิง: แท็บเล็ตแนวนอน 1000 × 625 logical px
- โครงหน้าผู้ป่วย: ราง workflow ซ้าย | ฉาก 3D กลาง | แผงข้อมูลขวา
- **Header = patient profile** สูง 58px สองบรรทัด: avatar 38px (มุมมีป้ายเพศ ♀/♂) · ชื่อ + ป้าย ESI + pain pill · อายุ · HN · เตียง · หมู่เลือด · แล้วข้อเท็จจริง: แพ้ยา/อาหาร (แดงถ้ามี) · โรคประจำตัว · GCS สั้น · รูม่านตา · เวลาใน ER (หลายรายการ = เลื่อนแนวนอน ขอบขวาจาง)
- **มุมขวาบนของหน้าผู้ป่วย = ปุ่มส่งต่อ F9 อย่างเดียว** (pill navy: ไอคอนส่ง · ชื่อขั้นปลายทาง · ป้ายคีย์ `F9`) · **แจ้งเตือน + ประวัติการบันทึก อยู่มุมซ้ายล่าง** (การ์ดลอยใต้ราง workflow) หน้าต่างแจ้งเตือนเปิดข้างปุ่ม
- ของที่ลอยมุมซ้ายล่าง (dock, แถบงานพยาบาล, ป้ายผู้ใช้) ห้ามทับกัน · แผงซ้ายที่เลื่อนได้เว้นล่าง ~76px ให้ป้ายผู้ใช้
- แผงขวา: แท็บบน → เนื้อหาเลื่อนในแผง · ทุกแท็บใช้ layout การ์ดเดียวกัน
- การ์ดหลายใบใช้ grid คอลัมน์คงที่ (แผน 3 คอลัมน์ · แล็บ 5 คอลัมน์) ขอบ/padding เท่ากันทุกใบ
- ระยะห่างใช้ชุด 4 / 6 / 8 / 10 / 12 / 16 · padding การ์ด 10–12
- **ทุกหน้าใช้ภาษาเดียวกับหน้าผู้ป่วย**: การ์ดนูน + `_InnerGloss` ทุกใบ · บนพื้นขาว/เทา = `_clyCardDeco` · **แผงซ้าย (ภาพรวม/ช่วงงาน) คงพื้นสีหลักกรมท่า** การ์ดเป็นกระจกโปร่ง `_lpCardDeco` + `_InnerGloss(dark)` · ตัวกรองบนกรมท่า = pill ขาวนูน ตัวอักษรกรมท่า
- หน้าภาพรวมผู้ป่วย = bento (ดู knowledge ข้อ 33) · ข้อมูลในแต่ละ widget เรียงอัตโนมัติ (ข้อ 34)

| **ป้าย ESI** | สีตามระดับ + `_glossGrad` + `_glossLift` ตัวอักษรขาว w700 |
| **ค่าแล็บ** | การ์ด tile: ชื่อ · ป้าย H/L แดง · `ค่า \| ค่าสูงสุดปกติ` · แถบจุด 10 จุด (`_labDots`) · ปกติไม่มีสี |

| **แถบแท็บ / ตัวกรอง** | ปุ่มกว้างเท่ากันเต็มแถบ · ที่เลือก = pill navy gloss |
| **Avatar ผู้บันทึก** | avatar 3D แพทย์/พยาบาล · หลายคน = ซ้อนกัน (stack) คนที่เลือกอยู่บน |
| **Toast แจ้งเตือน** | พื้นแดงทึบ · ป้าย label ขาว · padding 12 · ปุ่มปิด 20×20 |
| **Push notification** | ใช้ `ErNotify` (channel `er_critical`) เฉพาะเรื่องวิกฤต · แตะแล้วเปิดเคสตาม HN |
| **Workflow rail** | ขั้นที่ครบ = วงกลมเขียวทึบ ไม่มีวงนอก + ✓ · ขั้นปัจจุบัน navy |
| **Stepper** | อยู่บนสุดของแผง workflow · แต่ละหน้ามีชื่อ + สถานะครบ · ไม่แสดงบนหน้าแนะนำ |
| **ปุ่มหลัก** | pill navy `_glossGrad(_blue)` · ข้อความบอกผลที่จะเกิด ("ถัดไป", "ครบแล้ว · ขั้นต่อไป", "ไปช่องที่ขาด (n)") |
| **ปุ่มปิดแผง** | ปุ่ม collapse (`keyboard_double_arrow_left`) ชิดมุม ไม่ใช้ ✕ |
| **ไมค์** | **แตะเพื่อพูด / แตะเพื่อส่ง** (toggle) · แสดงเวลาที่อัด · ห้ามเปิดไมค์เอง |
| **ลิ้นชักขวา** | กว้าง 340–360 · พื้นขาว ขอบซ้าย + เงา · แตะพื้นที่ว่างปิด · ปุ่มหลักเต็มกว้างล่างสุด · ใช้กับวัด V/S ซ้ำ และส่งต่อ F9 |
| **ลิ้นชักส่งต่อ (F9)** | ตามหน้าจอการส่งต่อของ HOSxP: ส่งต่อห้อง · สถานะ (dropdown) · จำนวนเงินรอทำรายการชำระ (บาท ทศนิยม 2 แดงเมื่อ > 0) · จำนวนรายการยา · "ยืนยัน (F9)" · กด F9 ซ้ำ = ยืนยัน |
| **เวลาใต้กราฟ V/S** | จุด > 3 แสดงแค่เวลาแรก · ล่าสุด · ที่เลือก ขนาดเต็ม ไม่ย่อจนอ่านไม่ออก |
| **ปุ่มใหญ่ (`_navBtn`)** | ไอคอนห่างข้อความ 6 · ข้อความยาวตัด … ไม่ล้น |
| **ช่องกรอกในหน้าเต็ม (ลงทะเบียน)** | ป้ายชื่อเหนือช่อง w600 · ช่องพื้น `_panelSoft` ขอบ `_line` มุม 10 สูง 44 · ช่องบังคับมี * แดง · dropdown หน้าตาเดียวกับช่องพิมพ์ + ลูกศร |

## 7. Workflow & AI

- แต่ละ flow: **หน้าแนะนำ** (ไอคอน + ชื่อ + วัตถุประสงค์ + สิ่งที่ต้องกรอก + วิธีใช้) → **หนึ่งหน้าต่อหนึ่งช่อง** → **หน้าสรุป** → ยืนยัน
- หน้าแนะนำไม่แสดง title ซ้ำที่ header และไม่มี stepper
- **ไม่ใช้ generative UI** — ฟอร์มคงที่ตาม design language นี้ AI ทำหน้าที่เติมค่าในฟอร์ม
- คำพูดตีความลง **template ที่แพทย์เลือก** (ไม่สร้างกล่อง transcript แยก) · แก้ประโยคเก่าได้
- ทุกค่าที่ AI เปลี่ยนต้องมี diff animation:
  - เพิ่ม = ไฮไลต์เขียว + พิมพ์ทีละตัว
  - แก้ = ขีดฆ่าข้อความเดิม แล้วพิมพ์ข้อความใหม่
  - ลบ = ไฮไลต์แดง
- แผงขวาระหว่างทำ workflow เป็นข้อมูลที่บันทึกแล้วแบบ static (การสั่งทำใน workflow)
- **กรอกครบ หรือสั่ง "ข้าม"/"ขั้นต่อไป" → ไปหน้าตรวจสอบ (สรุป) ของขั้นนั้นก่อนเสมอ** ไม่ข้ามขั้นเงียบ ๆ · สั่งข้ามแล้วปุ่มเป็น "ข้ามขั้นนี้ · ขั้นต่อไป" แม้ยังไม่ครบ (knowledge ข้อ 42)
- ช่องไม่บังคับ (เช่น "บันทึกการตรวจแบบละเอียด") ไม่นับเป็นช่องที่ขาด

## 8. Motion & Performance

| ประเภท | ระยะเวลา | Curve |
|---|---|---|
| hover/เลือก/เปลี่ยนสีเล็ก | 160 – 220ms | `easeOutCubic` |
| เปลี่ยนหน้าใน workflow (slide ±0.22 + fade) | 320ms | `easeOutCubic` |
| ขยาย/หุบแผง (ตัว container ยืด) | 420 – 600ms | `easeInOutCubic` |
| ไฮไลต์ค่าที่เปลี่ยน | ค้าง 2.5s แล้วจาง | — |

- ทิศ animation บอกทิศการเดิน: ไปข้างหน้าเลื่อนซ้าย ย้อนกลับเลื่อนขวา
- วัดผลด้วย `flutter run --profile` บนเครื่องจริงเท่านั้น (debug ไม่มีความหมาย)
- เป้า: raster < 16.6ms/เฟรม ที่ 60Hz (แอปล็อกจอ 60Hz ใน `MainActivity`)
- **ห้าม** blur, animation วนตลอดเวลาบนหน้าที่มี WebView, WebView ที่ซ่อนแต่ยังวาดอยู่
- ใส่ `RepaintBoundary` รอบแผงที่อัปเดตแยกกัน · ซ่อนฉาก 3D (`Offstage`) เมื่อถูกบังทั้งหมด

## 9. ฉาก 3D

- อวัยวะ/กระดูกมาจาก **BodyParts3D** เท่านั้น การ map อวัยวะเป็น logic ไม่ใช่วาดเอง
- อาการที่ไม่ชี้อวัยวะชัด (ปวดท้อง คลื่นไส้) แสดงเป็น heatmap โซน
- ห้ามแก้ layer หลอดเลือด (vessel)
- สีบนหุ่นเป็นไปตามกฎสีข้อ 2 (แดง = บาดเจ็บ/ผิดปกติ)
