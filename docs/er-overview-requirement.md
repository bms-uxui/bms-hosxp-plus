# ER Overview — Requirement

หน้าแรกของโมดูล ER (HOSxP Plus V5) ใช้บนแท็บเล็ตแนวนอน ผู้ใช้หลักคือพยาบาลหัวหน้าเวรและแพทย์เวร

- แบบอ้างอิง: Figma `HOSXP V6 ER` node `96-1343`
- โค้ด: `lib/er/er_flow_home/er_flow_home_widget.dart`
- เส้นทาง: `Er_Flow_Home` / `hosxpplusv5://hosxpplusv5.com/erFlowHome`
- สถานะข้อมูล: **จำลองทั้งหมด** ยังไม่ต่อฐานข้อมูลจริง

---

## 1. เป้าหมายของหน้า

ตอบสามคำถามภายในสายตาเดียว โดยไม่ต้องกดเข้าไปดูอะไรก่อน

1. ตอนนี้มีคนอยู่ในห้องกี่คน ค้างเกินเกณฑ์กี่คน
2. คนค้างอยู่ที่ขั้นไหนของกระแสงาน ขั้นไหนเป็นคอขวด
3. มีเหตุการณ์อะไรเพิ่งเกิดขึ้นที่ต้องรู้

หน้านี้เป็นจุดตั้งต้น ไม่ใช่หน้าทำงาน งานรายคน (คัดกรอง ตรวจ สั่งยา จำหน่าย) เข้าจากแฟ้มผู้ป่วยเท่านั้น

หน้าเดียวจบ **ไม่มีการ์ดลอยทับฉาก** การกดชิปเปลี่ยนทั้งฉากและแผงซ้ายพร้อมกัน

### 2.1 แถบเมนู

เมนูเป็น **มุมมองของข้อมูลชุดเดียวกัน** ห้ามปนกับงาน

- ภาพรวม (หน้านี้)
- ผังเตียง → `Er_Bed_View`
- รายชื่อ → `ERHomepageCopy`
- ย้อนหลัง → `ERDashboard`
- แจ้งเตือน (ป้ายจำนวนที่ยังไม่อ่าน)

### 2.2 แผงข้อมูล (ซ้าย)

**ต้องเลื่อนขึ้นลงได้ทั้งแผง** ไม่ใช่เลื่อนเฉพาะท่อนล่าง เพราะบนจอเตี้ยกว่าแบบ เนื้อหาไม่พอแสดงครบ

**ต้องยุบ/กางได้** ปุ่มลูกศรคู่อยู่แถวเดียวกับหัวข้อ จัดกลางแนวตั้งเทียบกับหัวข้อ+คำโปรย (ห้ามมีป้ายชื่อหน้าเล็ก ๆ เหนือหัวข้อ) ยุบแล้วเหลือแถบ 40 px มีปุ่มกางกับชื่อหน้าแนวตั้ง คืนพื้นที่ให้ฉาก 3D

#### โหมดภาพรวม (ยังไม่เลือกชิป)

เรียงจากบนลงล่าง

1. **หัวข้อ** `ภาพรวมห้องฉุกเฉิน` + `กระแสงานตามเวลาจริง · อัปเดตทุก 1 นาที`
2. **ตัวเลขสรุป 4 ช่อง** (2×2) แต่ละช่องมี ป้าย · ตัวเลขใหญ่ · บรรทัดขยาย
   - ผู้ป่วยในห้องตอนนี้ — `วันนี้รวม N ราย`
   - ค้างเกินเกณฑ์ — เป็นสีแดงเมื่อ > 0
   - เวลาเฉลี่ยใน ER — เทียบสัปดาห์ก่อน
   - เตียงว่าง — `จาก N เตียง`
3. **กราฟผู้ป่วยเข้าออกรายชั่วโมง** (ดูข้อ 3)
4. **รายการแจ้งเตือน** (ดูข้อ 4)

#### โหมดช่วงงาน (เลือกชิปแล้ว)

1. **หัวข้อ** ชื่อช่วงงาน + ปุ่มปิดกลับไปภาพรวม
2. **ตัวเลขสรุป 4 ช่อง** ของช่วงนั้น — อยู่ในช่วงนี้ · ค้างเกินเกณฑ์ · เวลารอเฉลี่ย · ยังไม่ได้เตียง
3. **รายชื่อผู้ป่วย** เรียงตามความเสี่ยง (ESI ก่อน แล้วเวลารอ) พร้อมชิปกรอง 4 ตัว — ทั้งหมด · บนเตียง · ยังไม่ได้เตียง · เกินเกณฑ์

### 2.3 พื้นที่ฉาก (ขวา)

- **ชิปช่วงงาน** ลอยด้านบน 4 ปุ่มตาม Figma node `96-1345`: ภาพรวม · คัดกรอง · ตรวจรักษา · หลังการตรวจ
  - หนึ่งชิปครอบได้หลายขั้น — `ตรวจรักษา` = รอตรวจ + ตรวจแล้ว
  - กดแล้วเปลี่ยน **ทั้งฉากและแผงซ้าย** พร้อมกัน (Figma node `58-492`)
- **ภาพฉากกระแสงาน** ภาพเรนเดอร์จากแบบ (Figma node `148-2597`) — แท่นสามชั้นไล่ระดับ แต่ละชั้นเป็นห้องจริง 1 คัดกรอง · 2 ตรวจรักษา · 3 หลังการตรวจ
  - **ไม่มีป้ายลอยทับภาพ** ตัวเลขทั้งหมดอ่านจากแผงซ้าย การเลือกช่วงงานทำที่ชิปด้านบน
  - ไฟล์ `assets/images/flow/er_workflow_scene.png` ย่อเหลือกว้าง 1600 px
- **แถบสีระดับความเร่งด่วน** มุมขวาล่างของฉาก ESI 1–5 + ยังไม่คัดกรอง (ไม่มีหัวข้อ ER Workflow แล้ว)
- **การ์ดสรุปลอย 3 ใบ** ข้างแต่ละขั้น (Figma `96-1343` Group 351/352/353) — ชื่อช่วงงาน · จำนวน · บรรทัดเกินเกณฑ์ · โดนัทแบ่งตามระดับ ESI จริง กดแล้วเลือกช่วงงานเหมือนกดชิป
- **แถบรายชื่อเร่งด่วนด้านล่าง** (Figma `148-2610`) — การ์ดแนวนอนเลื่อนได้ เฉพาะคนที่ค้างเกินเกณฑ์ เรียงตามความเสี่ยง แต่ละใบมีรูป · ป้าย ESI · ชื่อ · เตียง · เวลาที่ค้าง · เหตุผล เลือกช่วงงานอยู่จะกรองเหลือเฉพาะช่วงนั้น
**การเลือกช่วงงานซิงก์สองทาง** — ชิปด้านบนกับแผงซ้าย อ่านและเขียนสถานะตัวเดียวกัน

### 2.4 แถบปักหมุด (ขวาสุด)

- **เมนูปักหมุด** ทางลัดงานที่ใช้บ่อย — รับผู้ป่วย · สั่งยา · สรุปเวร
- **ผู้ป่วยปักหมุด** รูปโปรไฟล์จริง วงแหวนรอบรูปบอกระดับ ESI แดงหนาเมื่อค้างเกินเกณฑ์ ป้ายรหัสเตียงมุมล่าง แตะแล้วกระโดดไปช่วงงานที่ผู้ป่วยคนนั้นอยู่ ปุ่ม `+` ท้ายรายการไว้ปักหมุดเพิ่ม

## 3. กราฟผู้ป่วยเข้าออกรายชั่วโมง

ต้องอ่านค่าได้จริง ไม่ใช่ดูรูปทรงอย่างเดียว

- เส้นกริดแนวนอน 3 เส้นพร้อมตัวเลขกำกับ
- ป้ายชั่วโมงใต้แกนทุก 6 ชั่วโมง (`00 น.` `06 น.` …)
- คำอธิบายสีด้านบน เข้า (น้ำเงิน) / ออก (เทา) พร้อมตัวเลขรวมทั้งวัน
- **แตะหรือลากนิ้วบนกราฟ** เพื่อเลือกชั่วโมง — แท่งที่เลือกเด่น แท่งอื่นจาง ตัวเลขด้านบนเปลี่ยนเป็นค่าของชั่วโมงนั้น ป้ายบอกช่วงเวลา `HH:00–HH:59 น.` กดปุ่มกากบาทเพื่อกลับไปดูยอดรวม

## 4. รายการแจ้งเตือน

แทนที่บล็อก "กระแสงาน" เดิมในแผงซ้าย (ตัวเลขต่อขั้นไปอยู่บนฉาก 3D และแท็บแล้ว ไม่ต้องแสดงซ้ำสามที่)

### ระดับ

| ระดับ | สี | ความหมาย |
|---|---|---|
| วิกฤต | `#EA4335` | ต้องลงมือทันที เช่น ESI 1 ยังไม่พบแพทย์ |
| เร่งด่วน | `#F97316` | จะกลายเป็นวิกฤตถ้าปล่อยไว้ เช่น เตียงใกล้เต็ม |
| เฝ้าระวัง | `#F9AB00` | ค้างผิดปกติแต่ยังไม่อันตราย เช่น ผลแล็บช้า |
| ปกติ | `#34A853` | เหตุการณ์ที่สำเร็จแล้ว ใช้ยืนยันว่างานเดิน |

### การ์ดหนึ่งใบ

- เวลาเกิดเหตุ — รูปแบบ `HH:mm น.` (ดูข้อ 11)
- หัวข้อ — สิ่งที่เกิด ไม่เกิน 2 บรรทัด
- รายละเอียด — ชื่อผู้ป่วย · เตียง · เหตุผล บรรทัดเดียว ตัดท้ายด้วย `…`
- จุดสีระดับชิดขวา
- **ใบระดับวิกฤต: พื้นแดงทึบ ตัวหนังสือขาว** พร้อมป้ายคำว่า `วิกฤต` ข้างเวลา ไอคอนตกใจแทนจุดสี และเงาแดงใต้การ์ด — ต้องอ่านออกจากอีกฝั่งของห้องโดยไม่ต้องเข้าไปดูใกล้

### ตัวกรอง

ชิป 4 ตัวตามระดับ กดเลือก = แสดงเฉพาะระดับนั้น กดซ้ำตัวเดิม = ล้างตัวกรอง หัวข้อแสดงจำนวนรายการที่ผ่านตัวกรอง กรองแล้วไม่เหลือ → `ไม่มีการแจ้งเตือนในระดับนี้`

### กติกาเนื้อหา

- เป็น **เหตุการณ์ที่เกิดขึ้น ณ เวลาหนึ่ง** ไม่ใช่สถานะสะสม (สถานะสะสมอยู่ในตัวเลขสรุปกับฉาก 3D แล้ว)
- เรียงใหม่ก่อนเสมอ
- ต้องบอกได้ว่า *ใคร* หรือ *อะไร* ไม่ใช่แค่ว่ามีปัญหา

## 7. ข้อจำกัดทางเทคนิค

- **ฟอนต์** ต้องใช้ไฟล์ที่ฝังในแอป (`NotoSansThai`, `DMSans`) ห้ามใช้ `google_fonts` — แท็บเล็ตในห้องฉุกเฉิน TLS ใช้ไม่ได้ พอโหลดฟอนต์ไม่ผ่านจะพังทั้งชั้นข้อความ
- **ฉาก 3D** three.js ใน `webview_flutter` เสิร์ฟจาก `HttpServer` บน 127.0.0.1 ต้องแยก conditional import เพราะ `dart:io` พัง `flutter build web`
- **ป้ายภาษาไทยบนฉาก** เป็นวิดเจ็ต Flutter ลอยทับตามพิกัดที่ฝั่ง 3D ส่งกลับ ไม่ได้วาดใน WebGL ตัวหนังสือจึงคม
- **พื้นที่ฉากจริง** ~663×375 logical px บนแท็บเล็ต 1280×800 เตี้ยกว่าในแบบ (799×599) ต้องเผื่อเรื่องนี้เวลาจัดกล้อง

## 8. ข้อมูลที่ยังไม่มีในฐานข้อมูลจริง

โค้ดเบสเดิมมีแกนเดียวที่เกี่ยวข้องคือ `สภาพผู้ป่วย` (เดินมา / นั่งรถเข็น) **ไม่มี** entity เตียง ไม่มีโซน รหัสเตียง A1–B5 และสถานะว่างเป็นของสมมติทั้งหมด

ต้องเพิ่มอย่างน้อย

- `patient.zone` — ขั้นของกระแสงานที่ผู้ป่วยอยู่
- `patient.bed_id` — เตียงที่ครองอยู่ (null = ยังไม่ได้เตียง)
- `bed.status` — ว่าง / ครอง / ปิดใช้
- `bed.placement` — เตียง / รถเข็น / เก้าอี้นั่งรอ

และคิวเหตุการณ์สำหรับรายการแจ้งเตือน (เวลา · ระดับ · หัวข้อ · อ้างอิงผู้ป่วยหรือทรัพยากร)

## 9. ปฏิสัมพันธ์

- **ทุก element ที่กดได้ต้องมี ripple** ใช้ `Material` + `InkWell` เสมอ ไม่ใช่ `GestureDetector`
  - พื้นหลังต้องอยู่บน `Material` ไม่ใช่บน `Container` ที่ครอบ `InkWell` ไว้ ไม่งั้น ripple จะถูกทับจนมองไม่เห็น
  - ตั้ง `clipBehavior: Clip.antiAlias` ให้ ripple ถูกตัดตามมุมโค้ง

## 11. รูปแบบเวลา

**เวลานาฬิกาต้องลงท้ายด้วย `น.` เสมอ** ทุกที่ในโมดูล — นาฬิกาบนแถบเมนู เวลาการแจ้งเตือน บันทึกกิจกรรม แกนเวลาของกราฟสัญญาณชีพ

```
10:22 น.     ถูก
10:22        ผิด
```

ใช้ผ่านตัวช่วย `_clock(String hhmm)` ไม่ใช่เขียนต่อสตริงเอง เก็บข้อมูลดิบเป็น `HH:mm` แล้วค่อยจัดรูปแบบตอนแสดง

**ระยะเวลา** (duration) คนละเรื่องกับเวลานาฬิกา ใช้ `_hm(int minutes)` เช่น `22 นาที` · `2 ชม. 35 น.`

## 12. ฉากสามมิติของแต่ละช่วงงาน — ยังไม่ทำ

ตามแบบ `58-492` เมื่อเลือกชิปช่วงงาน ฝั่งขวาควรเป็นฉาก **Patient List 3D** — เรียงผู้ป่วยตามความฉุกเฉิน แบ่งตามสถานะการวางตัว (เตียง · รถเข็น · นั่งรอ)

ตอนนี้ยังใช้ฉากอาคารเดิม แค่ไฮไลต์ห้องของช่วงงานที่เลือกและหรี่ห้องอื่นลง โมเดลของฉากใหม่ยังไม่ได้ปั้น
